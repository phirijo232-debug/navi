# Customer Directory and HR Security Details

## Purpose
Make the Customers menu show real borrower accounts with loan-management statistics, and make HR employee security details visible when selected.

## Progress
- [x] (2026-10-17) Trace the Customers and HR view navigation, APIs, and role gates.
- [x] (2026-10-17) Load and render customer accounts together with their scoped loan records.
- [x] (2026-10-17) Show safe HR security summaries and permissions without exposing device credentials.
- [x] (2026-10-17) Verify the server starts and the existing suite remains green.

## Decision Log
- (2026-10-17) Keep customer identity sourced from the credential-stripped `/users` endpoint and loan metrics sourced from the scoped loan-management endpoint.
- (2026-10-17) HR security details will show only safe device counts/last-seen metadata and configured restrictions; raw trusted-device tokens remain private.
- (2026-10-17) Allow the documented `franchise_admin` role through the admin UI login gate so its authorized HR view is reachable.

## Surprises and Discoveries
- Customers rendered immediately after `/users`, before the loan list finished loading. The later loan fetch updated dashboard data but never refreshed the visible customer cards.
- HR cards only showed identity and a single notification restriction toggle; no selectable details panel showed account security metadata or permission state.
- The admin OTP client gate rejected `franchise_admin` even though the API and HR view authorize that role.

## Outcomes and Retrospective
Customers now excludes staff records and renders its loan metrics only after the scoped Loan Management records finish loading. HR employee cards have expandable account security and permission details, including safe trusted-device counts and last-seen metadata. The client login gate now accepts the franchise employee role that the backend already authorizes.
